## 1. Descripción

**uv** es un gestor de paquetes y proyectos para Python desarrollado por **Astral** (los creadores de Ruff y ty). Reúne en un único binario las funciones de:

| Herramienta tradicional | Equivalente en uv |
|---|---|
| pip, pip-tools | `uv pip install`, `uv pip compile`, `uv pip sync` |
| venv, virtualenv | `uv venv` (y entornos automáticos) |
| pipx | `uv tool install`, `uvx` |
| Poetry, PDM | `uv init`, `uv add`, `uv lock`, `uv sync`, `uv build`, `uv publish` |
| pyenv | `uv python install`, `uv python pin` |

**Ventajas:**
- Entre 10 y 100 veces más rápido que pip gracias a su caché global y resolución en paralelo.
- Instala y gestiona versiones de Python automáticamente.
- Archivo de bloqueo `uv.lock` multiplataforma.
- Usa los estándares: `pyproject.toml` con `[project]`, `[dependency-groups]` (PEP 735), scripts PEP 723.
- Binario independiente: no necesita Python previo para instalarse.

**Limitaciones:**
- Sigue en versiones `0.x`: algunas opciones cambian entre versiones menores (consulte el registro de cambios al actualizar).
- Algunas funciones se publican primero como *preview*.

| Si necesita… | Opción |
|---|---|
| Un único gestor rápido para todo el ciclo | **uv** |
| Mantener un proyecto existente en Poetry | Poetry (o migrar a uv) |
| Paquetes no Python (CUDA, GDAL) | conda / pixi |

## 2. Instalación

Instalador oficial (recomendado):

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh                                   # Linux/macOS
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex" # Windows
```

Otras opciones:

```bash
brew install uv              # macOS
winget install astral-sh.uv  # Windows
pipx install uv              # Con pipx
```

Comprobar y actualizar:

```bash
uv --version
uv self update               # Solo si se usó el instalador oficial
```

Autocompletado:

```bash
echo 'eval "$(uv generate-shell-completion bash)"' >> ~/.bashrc
echo 'eval "$(uvx --generate-shell-completion bash)"' >> ~/.bashrc
```

## 3. Conceptos clave

| Concepto | Descripción |
|---|---|
| Proyecto | Carpeta con `pyproject.toml`; uv gestiona su entorno y bloqueo. |
| `uv.lock` | Bloqueo universal: versiones exactas y hashes para todas las plataformas. |
| `.venv` | Entorno del proyecto; uv lo crea y sincroniza automáticamente. |
| `.python-version` | Versión de Python fijada para el proyecto. |
| Sincronizar | Dejar `.venv` exactamente igual que el bloqueo. |
| Grupo de dependencias | Dependencias de desarrollo (`[dependency-groups]`, PEP 735). |
| Herramienta | Aplicación de terminal instalada en un entorno aislado (`uv tool`). |
| Caché global | Paquetes descargados compartidos entre proyectos (enlazados, no copiados). |
| Espacio de trabajo | Varios paquetes en un repositorio con un único bloqueo. |

**Flujo general:** `uv add` modifica `pyproject.toml` → actualiza `uv.lock` → sincroniza `.venv`. `uv run` comprueba todo antes de ejecutar.

## 4. Gestionar versiones de Python

```bash
uv python list                        # Versiones disponibles e instaladas
uv python install 3.13                # Instalar una versión
uv python install 3.12 3.13 3.14      # Varias
uv python install pypy@3.11           # Otras implementaciones
uv python upgrade 3.13                # Última versión de parche
uv python find 3.13                   # Ruta del intérprete
uv python pin 3.13                    # Crea .python-version en el proyecto
uv python pin --global 3.13           # Por defecto para el usuario
uv python uninstall 3.12
uv python install 3.13 --default      # Expone «python» y «python3» en el PATH
```

> uv descarga Python automáticamente cuando un comando lo necesita y no está instalado.

## 5. Crear un proyecto

```bash
uv init mi-app                  # Aplicación (por defecto)
uv init --package mi-cli        # Aplicación empaquetada, con src/ y scripts
uv init --lib mi-libreria       # Librería con src/ y py.typed
uv init --script utilidad.py    # Script PEP 723
uv init --python 3.13 mi-app
uv init                         # En la carpeta actual
```

Estructura (`uv init --package mi-cli`):

```
mi-cli/
├── .git/
├── .gitignore
├── .python-version
├── README.md
├── pyproject.toml
└── src/
    └── mi_cli/
        └── __init__.py
```

`pyproject.toml` generado:

```toml
[project]
name = "mi-cli"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.13"
dependencies = []

[project.scripts]
mi-cli = "mi_cli:main"

[build-system]
requires = ["uv_build>=0.9,<0.14"]
build-backend = "uv_build"
```

> El *backend* `uv_build` es el que genera uv por defecto. Puede sustituirlo por `hatchling`, `setuptools` o `poetry-core` si lo prefiere.

## 6. Gestionar dependencias

```bash
uv add httpx                          # Añade con restricción >= versión actual
uv add "httpx>=0.27,<1"
uv add "fastapi[standard]"
uv add httpx pydantic rich            # Varias
uv add --dev pytest ruff mypy         # Grupo «dev»
uv add --group docs mkdocs-material   # Otro grupo
uv add --optional pdf weasyprint      # Extra del paquete
uv add git+https://github.com/org/repo --tag v1.2.0
uv add --editable ./libs/utilidades   # Ruta local
uv add -r requirements.txt            # Importar un archivo de requisitos
uv add "pywin32 ; sys_platform == 'win32'"

uv remove httpx
uv remove --dev ruff

uv tree                               # Árbol de dependencias
uv tree --outdated                    # Marca las que tienen versión nueva
uv tree --depth 1
uv tree --invert --package urllib3    # ¿Quién depende de urllib3?
```

Resultado en `pyproject.toml`:

```toml
[project]
dependencies = [
    "httpx>=0.28.1",
    "pydantic>=2.10",
]

[project.optional-dependencies]
pdf = ["weasyprint>=63"]

[dependency-groups]
dev = ["pytest>=8.3", "ruff>=0.8", "mypy>=1.13"]
docs = ["mkdocs-material>=9.5"]
```

## 7. Bloqueo y sincronización

```bash
uv lock                               # Resuelve y escribe uv.lock
uv lock --check                       # Falla si el bloqueo está desactualizado (CI)
uv lock --upgrade                     # Actualiza todo dentro de las restricciones
uv lock --upgrade-package httpx       # Actualiza solo un paquete

uv sync                               # Instala lo bloqueado (incluye grupo dev) y elimina lo que sobra
uv sync --locked                      # Error si uv.lock no coincide con pyproject.toml
uv sync --frozen                      # Usa uv.lock tal cual, sin comprobar
uv sync --no-dev                      # Sin dependencias de desarrollo
uv sync --group docs                  # Añadir un grupo
uv sync --only-group test             # Solo un grupo
uv sync --all-extras / --extra pdf
uv sync --inexact                     # No elimina paquetes que sobran
```

| Opción | Cuándo |
|---|---|
| `--locked` | CI: verificar que el bloqueo está al día e instalarlo. |
| `--frozen` | Docker: instalar sin resolver (más rápido). |
| `--no-dev` | Producción. |

Exportar el bloqueo a otros formatos:

```bash
uv export --format requirements-txt -o requirements.txt
uv export --no-dev --no-hashes -o requirements.txt
uv export --format pylock.toml -o pylock.toml        # Estándar PEP 751
```

Protección frente a versiones recién publicadas (ataques a la cadena de suministro):

```toml
[tool.uv]
exclude-newer = "7 days"         # Ignora versiones publicadas en los últimos 7 días
```

## 8. Ejecutar código: `uv run`

```bash
uv run python script.py
uv run pytest -q
uv run mi-cli --help                       # Script del proyecto
uv run -m http.server 8000                 # Módulo
uv run --with rich python -c "import rich" # Dependencia temporal adicional
uv run --python 3.12 pytest                # Con otra versión de Python
uv run --no-sync python script.py          # Sin sincronizar antes
uv run --env-file .env python app.py       # Cargar variables de entorno
```

Antes de ejecutar, `uv run` comprueba que `uv.lock` y `.venv` están al día y los actualiza si es necesario. No hace falta activar el entorno.

> Si lo prefiere, puede activar `.venv` como cualquier entorno virtual (`source .venv/bin/activate`).

## 9. Scripts de un solo archivo (PEP 723)

```bash
uv init --script informe.py --python 3.13
uv add --script informe.py httpx rich      # Añade dependencias al bloque de metadatos
uv run informe.py                          # Crea un entorno temporal y ejecuta
uv lock --script informe.py                # Bloqueo junto al script (informe.py.lock)
```

```python
#!/usr/bin/env -S uv run --script
# /// script
# requires-python = ">=3.13"
# dependencies = ["httpx>=0.28", "rich>=13"]
# ///
import httpx
from rich.table import Table
from rich.console import Console

datos = httpx.get("https://pypi.org/pypi/uv/json", timeout=10).json()
tabla = Table("Campo", "Valor")
tabla.add_row("Versión", datos["info"]["version"])
tabla.add_row("Licencia", datos["info"]["license"] or "-")
Console().print(tabla)
```

Con la línea *shebang*, el archivo se ejecuta directamente en Linux/macOS (`chmod +x informe.py && ./informe.py`).

## 11. Interfaz compatible con pip: `uv pip` y `uv venv`

Para proyectos que siguen con `requirements.txt` o para migrar poco a poco:

```bash
uv venv                                 # Crea .venv (muy rápido)
uv venv --python 3.12 .venv-312
uv venv --seed                          # Incluye pip en el entorno

uv pip install requests
uv pip install -r requirements.txt
uv pip install -e ".[dev]"
uv pip uninstall requests
uv pip list / freeze / show requests / tree / check

uv pip compile requirements.in -o requirements.txt                 # Como pip-tools
uv pip compile pyproject.toml --generate-hashes -o requirements.txt
uv pip compile --universal requirements.in -o requirements.txt     # Válido para todas las plataformas
uv pip sync requirements.txt                                       # Como pip-sync
```

> `uv pip` actúa sobre el entorno activo o sobre `.venv`; nunca sobre el Python del sistema salvo con `--system`.

## 12. Espacios de trabajo (*workspaces*)

Varios paquetes en un mismo repositorio con un único `uv.lock`:

```
monorepo/
├── pyproject.toml           # Raíz del espacio de trabajo
├── uv.lock
└── paquetes/
    ├── nucleo/pyproject.toml
    ├── api/pyproject.toml
    └── worker/pyproject.toml
```

```toml
# pyproject.toml (raíz)
[project]
name = "plataforma"
version = "0.1.0"
requires-python = ">=3.13"
dependencies = ["api", "worker"]

[tool.uv.workspace]
members = ["paquetes/*"]

[tool.uv.sources]
api = { workspace = true }
worker = { workspace = true }
```

```toml
# paquetes/api/pyproject.toml
[project]
name = "api"
version = "0.1.0"
dependencies = ["nucleo", "fastapi>=0.115"]

[tool.uv.sources]
nucleo = { workspace = true }
```

```bash
uv sync --all-packages              # Instala todos los miembros
uv run --package api uvicorn api.main:app
uv add --package worker celery
uv build --package nucleo
```

## 13. Construir, versionar y publicar

```bash
uv version                          # Muestra la versión del proyecto
uv version --bump patch             # 0.1.0 → 0.1.1
uv version --bump minor
uv version 1.0.0

uv build                            # dist/*.whl y dist/*.tar.gz
uv build --wheel
uv publish                          # A PyPI (token en UV_PUBLISH_TOKEN o publicación de confianza)
uv publish --index testpypi
```

Configurar TestPyPI:

```toml
[[tool.uv.index]]
name = "testpypi"
url = "https://test.pypi.org/simple/"
publish-url = "https://test.pypi.org/legacy/"
explicit = true
```

> En GitHub Actions, `uv publish` admite **publicación de confianza** (OIDC) sin tokens: configure el editor de confianza en PyPI y conceda `id-token: write` al trabajo.

## 14. Índices privados y fuentes

```toml
[[tool.uv.index]]
name = "interno"
url = "https://pypi.empresa.local/simple/"
explicit = true                    # Solo para paquetes que lo indiquen

[tool.uv.sources]
utilidades-internas = { index = "interno" }
mi-lib = { git = "https://github.com/org/mi-lib", tag = "v2.0.0" }
herramienta = { path = "../herramienta", editable = true }
torch = [
  { index = "pytorch-cpu", marker = "sys_platform != 'darwin'" },
]
```

Credenciales por variables de entorno (el nombre del índice en mayúsculas):

```bash
export UV_INDEX_INTERNO_USERNAME=usuario
export UV_INDEX_INTERNO_PASSWORD=token
```

> Por defecto uv usa la estrategia `first-index`: toma un paquete del **primer** índice donde lo encuentra. Esto protege frente a la confusión de dependencias, a diferencia de `--extra-index-url` en pip.

## 15. Configuración

uv lee la configuración de `[tool.uv]` en `pyproject.toml`, de `uv.toml` y del archivo de usuario (`~/.config/uv/uv.toml`; en Windows `%APPDATA%\uv\uv.toml`).

```toml
[tool.uv]
default-groups = ["dev", "test"]       # Grupos que sync instala por defecto
required-version = ">=0.9"             # Versión mínima de uv
exclude-newer = "7 days"
compile-bytecode = true
link-mode = "copy"                     # Útil si la caché está en otro disco
python-preference = "managed"          # Preferir Pythons gestionados por uv
```

Variables de entorno frecuentes:

| Variable | Uso |
|---|---|
| `UV_PYTHON` | Versión de Python a usar. |
| `UV_CACHE_DIR` | Ubicación de la caché. |
| `UV_COMPILE_BYTECODE=1` | Compilar a `.pyc` al instalar (contenedores). |
| `UV_LINK_MODE=copy` | Copiar en lugar de enlazar desde la caché. |
| `UV_NO_SYNC=1` | `uv run` no sincroniza. |
| `UV_PROJECT_ENVIRONMENT` | Ruta del entorno del proyecto (p. ej. `/opt/venv`). |
| `UV_FROZEN=1` / `UV_LOCKED=1` | Comportamiento de bloqueo en CI. |

Caché:

```bash
uv cache dir
uv cache clean
uv cache prune --ci              # Reduce la caché para guardarla en CI
```

## 16. uv en CI y Docker

### 16.1 GitHub Actions

```yaml
jobs:
  pruebas:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python: ["3.12", "3.13", "3.14"]
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v6
        with:
          enable-cache: true
          python-version: ${{ matrix.python }}
      - run: uv sync --locked --all-extras
      - run: uv run ruff check .
      - run: uv run pytest
```

### 16.2 Docker

```dockerfile
FROM python:3.13-slim
COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/

ENV UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy UV_NO_DEV=1
WORKDIR /app

# 1. Dependencias (capa reutilizable mientras no cambie el bloqueo)
RUN --mount=type=cache,target=/root/.cache/uv \
    --mount=type=bind,source=uv.lock,target=uv.lock \
    --mount=type=bind,source=pyproject.toml,target=pyproject.toml \
    uv sync --locked --no-install-project

# 2. Código del proyecto
COPY . /app
RUN --mount=type=cache,target=/root/.cache/uv uv sync --locked

ENV PATH="/app/.venv/bin:$PATH"
CMD ["mi-app"]
```

> Fije la versión de la imagen de uv (`ghcr.io/astral-sh/uv:0.13`) en producción para builds reproducibles.

## 17. Migrar desde otras herramientas

| Desde | Pasos |
|---|---|
| `requirements.txt` | `uv init --bare` y `uv add -r requirements.txt`; después `uv add --dev -r requirements-dev.txt`. |
| Poetry | `uvx migrate-to-uv` convierte `pyproject.toml` y genera `uv.lock`. Revise grupos y fuentes. |
| pipx | `uv tool install` para cada herramienta de `pipx list`. |
| pyenv | `uv python install` y `uv python pin`; los archivos `.python-version` son compatibles. |
| pip-tools | `uv pip compile` / `uv pip sync` con los mismos archivos `.in`/`.txt`. |

## 18. Ejemplo práctico completo

**API de tareas** con FastAPI: proyecto empaquetado con Python fijado, grupos de dependencias, pruebas, bloqueo verificado, un script de mantenimiento PEP 723 y una imagen Docker.

### 18.1 Creación

```bash

uv add --group docs mkdocs-material
```

### 18.2 `pyproject.toml`

description = "API REST para gestionar tareas"

    "sqlmodel>=0.0.22",
]

[project.scripts]

[dependency-groups]

docs = ["mkdocs-material>=9.5"]

[tool.pytest.ini_options]

[build-system]

build-backend = "uv_build"

### 18.3 Código

`src/tareas_api/main.py`:

```python
from collections.abc import Iterator
from contextlib import asynccontextmanager
from typing import Annotated

from fastapi import Depends, FastAPI, HTTPException, status
from sqlmodel import Field, Session, SQLModel, create_engine, select

MOTOR = create_engine("sqlite:///tareas.db", connect_args={"check_same_thread": False})


class TareaBase(SQLModel):
    titulo: str = Field(min_length=1, max_length=120)
    completada: bool = False


class Tarea(TareaBase, table=True):
    id: int | None = Field(default=None, primary_key=True)


def sesion() -> Iterator[Session]:
    with Session(MOTOR) as s:
        yield s


SesionDep = Annotated[Session, Depends(sesion)]


@asynccontextmanager
async def ciclo_vida(_: FastAPI):
    SQLModel.metadata.create_all(MOTOR)
    yield


app = FastAPI(title="Tareas", lifespan=ciclo_vida)


@app.get("/tareas")
def listar(s: SesionDep) -> list[Tarea]:
    return list(s.exec(select(Tarea)).all())


@app.post("/tareas", status_code=status.HTTP_201_CREATED)
def crear(datos: TareaBase, s: SesionDep) -> Tarea:
    tarea = Tarea.model_validate(datos)
    s.add(tarea)
    s.commit()
    s.refresh(tarea)
    return tarea


@app.patch("/tareas/{id_}/completar")
def completar(id_: int, s: SesionDep) -> Tarea:
    tarea = s.get(Tarea, id_)
    if tarea is None:
        raise HTTPException(status_code=404, detail="Tarea no encontrada")
    tarea.completada = True
    s.commit()
    s.refresh(tarea)
    return tarea


def ejecutar() -> None:
    import uvicorn

    uvicorn.run("tareas_api.main:app", host="0.0.0.0", port=8000)
```

`tests/test_api.py`:

```python
from collections.abc import Iterator

import pytest
from fastapi.testclient import TestClient
from sqlmodel import Session, SQLModel, create_engine
from sqlmodel.pool import StaticPool

from tareas_api.main import app, sesion


@pytest.fixture
def cliente() -> Iterator[TestClient]:
    motor = create_engine("sqlite://", connect_args={"check_same_thread": False}, poolclass=StaticPool)
    SQLModel.metadata.create_all(motor)

    def sesion_prueba() -> Iterator[Session]:
        with Session(motor) as s:
            yield s

    app.dependency_overrides[sesion] = sesion_prueba
    yield TestClient(app)
    app.dependency_overrides.clear()


def test_crear_y_completar(cliente: TestClient) -> None:
    r = cliente.post("/tareas", json={"titulo": "Revisar informe"})
    assert r.status_code == 201
    id_ = r.json()["id"]
    assert cliente.patch(f"/tareas/{id_}/completar").json()["completada"] is True
    assert len(cliente.get("/tareas").json()) == 1


def test_titulo_vacio(cliente: TestClient) -> None:
    assert cliente.post("/tareas", json={"titulo": ""}).status_code == 422
```

### 18.4 Script de mantenimiento (`scripts/exportar.py`)

```python
# /// script
# requires-python = ">=3.13"
# dependencies = ["httpx>=0.28"]
# ///
"""Exporta las tareas pendientes de la API a CSV."""
import csv
import sys

import httpx

URL = sys.argv[1] if len(sys.argv) > 1 else "http://localhost:8000"
tareas = [t for t in httpx.get(f"{URL}/tareas", timeout=10).json() if not t["completada"]]
escritor = csv.DictWriter(sys.stdout, fieldnames=["id", "titulo"], extrasaction="ignore", delimiter=";")
escritor.writeheader()
escritor.writerows(tareas)
```

## 19. Errores frecuentes

| Error | Causa | Solución |
|---|---|---|
| `The lockfile at uv.lock needs to be updated` (con `--locked`) | Se cambió `pyproject.toml` sin bloquear. | `uv lock` y versione `uv.lock`. |
| `No solution found when resolving dependencies` | Restricciones incompatibles o `requires-python` demasiado amplio. | Lea el árbol de conflicto y ajuste restricciones o `requires-python`. |
| `Failed to hardlink files; falling back to full copy` | Caché y proyecto en discos distintos. | `UV_LINK_MODE=copy` para silenciar el aviso. |
| `uv: command not found` tras instalar | El directorio de binarios no está en el `PATH`. | Reabra la terminal o ejecute `uv tool update-shell`. |
| El IDE no detecta el entorno | Aún no existe `.venv`. | `uv sync` y seleccione `.venv/bin/python`. |
| `uv pip install` falla con «No virtual environment found» | No hay entorno activo ni `.venv`. | `uv venv` primero, o `--system` en contenedores. |
| Paquete interno resuelto desde PyPI | Índice privado no asignado al paquete. | Use `explicit = true` y `[tool.uv.sources]`. |
| Comportamiento distinto tras actualizar uv | Cambios en versiones `0.x`. | Fije `required-version` y revise el registro de cambios. |

## 20. Buenas prácticas

- Use `uv init` + `uv add` + `uv run` como flujo principal; reserve `uv pip` para proyectos heredados.
- **Versione `uv.lock` y `.python-version`**.
- En CI, use `uv sync --locked` (o `uv lock --check`) para detectar bloqueos desactualizados.
- En Docker, separe la capa de dependencias (`--no-install-project`) de la del código y use `--frozen` o `--locked`.
- Declare las dependencias de desarrollo en `[dependency-groups]`.
- Fije la versión de uv del equipo con `required-version` y en las imágenes de CI.
- Use `exclude-newer` para retrasar la adopción de versiones recién publicadas.
- Asigne los paquetes internos a su índice privado con `explicit = true`.
- Para utilidades de un archivo, use scripts PEP 723 con `uv run`, en lugar de instalar dependencias globales.
- Use `uvx` para herramientas ocasionales y `uv tool install` para las de uso diario.
